# ТЗ модуля `atomic_model.initialization`

**Статус:** детализированная спецификация перед реализацией  
**Дата:** 2026-09-27  
**Связанные решения:** ADR-0093, ADR-0094, ADR-0095, ADR-0097

## 1. Роль модуля

`atomic_model.initialization` создаёт начальное состояние поверх готовой неизменяемой топологии и обрабатывает ручную сборку структуры до старта. Он не выполняет акты облучения и не изменяет границу после перехода в состояние «Симуляция».

Модуль получает `Topology`, конфигурацию режима, `seed_init` и возвращает валидный `SimulationState` либо понятную ошибку конфигурации. Любой результат должен пройти проверки вместимости и связности из `topology`.

## 2. Общие определения

| Обозначение | Значение |
|---|---|
| `N0` | Число узлов фиксированной упорядоченной решётки в области металла. |
| `NV` | Число вакансий в узлах области металла. |
| `NI` | Число межузельных атомов. |
| `NAs` | Число внешних поверхностных дефектных атомов (адатомов), размещённых вне области металла. |
| `N_atoms` | Общее число атомов: `N0 − NV + NI + NAs`. |
| `seed_init` | Сохранённое начальное состояние RNG для воспроизводимой генерации. |

Счётчики относятся к фактической занятости, а не к пожеланию пользователя. После каждой успешной подготовительной ручной операции они пересчитываются и немедленно передаются в `SimulationState` и панель.

## 3. Режимы создания

| Режим | Вход пользователя | Обязательный результат |
|---|---|---|
| `ordered` — полностью упорядоченная | Размерность, область металла, `seed_init` | `NV=NI=NAs=0`, `N_atoms=N0`; каждый металлический узел занят. |
| `random_defective` — абсолютно случайная дефектная | `seed_init`, независимые `μ` и `σ` для трёх категорий | Счётчики независимо получены из усечённых нормальных распределений; `N_atoms` может быть меньше, равен или больше `N0`. |
| `explicit_defective` — явно заданная | `NV`, `NI`, `NAs` | Три значения независимы; конфигурация удовлетворяет вместимости и связности. |
| `symmetric_defective` — симметричная дефектная | `NV`, `NI`, `NAs` | `N_atoms=N0` и `NI+NAs=NV`; отдельных пар «вакансия—дефект» не создаётся. |

`manual_edit` не является пятым режимом: это способ изменить подготовленную конфигурацию или переместить атом на паузе после старта.

## 4. Случайная дефектная генерация

Для каждой категории независимо разыгрывается усечённая нормальная величина с последующим дискретным округлением до целого:

| Категория | Стартовое `μ` | Стартовое `σ` | Границы |
|---|---:|---:|---|
| Вакансии `NV` | `0,05N0` | `0,02N0` | `0 ≤ NV ≤ N0` |
| Межузлия `NI` | `0,05N0` | `0,02N0` | `0 ≤ NI ≤ C_I` |
| Адатомы `NAs` | `0,01N0` | `0,01N0` | `0 ≤ NAs ≤ C_As` |

`C_I` и `C_As` — вместимости соответствующих свободных позиций готовой топологии с учётом требования связности. Панель позволяет менять все шесть параметров до старта; значения не зашиваются в код как единственная физическая модель.

Алгоритм обязан:

1. создать локальный RNG из `seed_init`;
2. разыграть три количества независимо друг от друга;
3. детерминированно выбирать размещения на основе того же RNG;
4. отбрасывать только геометрически недопустимые кандидаты размещения, а не связывать категории попарно;
5. при невозможности разместить уже разыгранное число атомов за ограниченное число детерминированных попыток вернуть `INITIAL_CONFIGURATION_INFEASIBLE`, не создавая частичного состояния.

Повторный запуск с теми же топологией, режимом, параметрами и `seed_init` обязан вернуть одинаковые счётчики, позиции и журнал подготовки.

## 5. Размещение начальных дефектов

1. Начать с заполненной упорядоченной решётки.
2. Выбрать `NV` различных узлов области металла и освободить их.
3. Разместить `NI` атомов в свободных межузельных позициях, только если каждый остаётся связанным через занятый `contact_graph` с металлом.
4. Разместить `NAs` атомов на свободных внешних узловых или внешних межузельных позициях, только если образуется связная цепочка до металла.
5. Выполнить `Topology.validate_occupancy`; при ошибке не фиксировать состояние.

Межузельные и внешние дефекты начальной конфигурации независимы от вакансий: наличие вакансии не создаёт обязательный межузельный атом, а избыток атомов над `N0` допустим в случайном и явно заданном режимах.

## 6. Ручный редактор

### До первого акта — состояние «Подготовка»

В отдельной вкладке доступны:

- 2D: построение и изменение ортогональной замкнутой границы области металла;
- 2D и 3D: добавление атома, удаление атома и перенос атома на допустимую позицию;
- просмотр `N_atoms`, `NV`, `NI`, `NAs` до и после планируемой операции.

В 3D ручное рисование произвольной объёмной границы не входит в текущую версию: доступна настройка прямоугольного параллелепипеда до старта.

Изменение границы создаёт новую подготовительную топологию; после успешной проверки она попадает в единый checkpoint. При изменении границы все существующие атомы должны оставаться на существующих валидных позициях, иначе действие отклоняется целиком.

### После первого акта — состояние «Симуляция»

- граница области металла и поле перемещений заблокированы навсегда для этой траектории;
- добавить или удалить атом вручную нельзя;
- на паузе разрешён только перенос уже существующего атома;
- перенос создаёт следующую запись единой истории с типом `manual_edit`, но не является актом гамма-облучения.

Любая ручная операция атомарна: до её фиксации проверяются существование позиции, вместимость, запрет возвращать красный атом в металл и контактная связность. При отказе состояние, seed и история не меняются.

## 7. Контракты команд и состояния

| Команда | Предусловие | Успешный результат |
|---|---|---|
| `configure_initialization` | Состояние «Подготовка» | Обновлена конфигурация режима, состояние ещё не создано/пересоздано. |
| `build_initial_state` | Валидная топология и конфигурация | Новый валидный `SimulationState`, счётчики и `seed_init`. |
| `edit_metal_boundary` | 2D, «Подготовка» | Новая подготовительная топология и checkpoint. |
| `add_atom` / `remove_atom` | «Подготовка» | Валидное подготовительное состояние и обновлённые счётчики. |
| `move_atom` | «Подготовка» либо «Симуляция» на паузе | Атом перемещён, история и метрики обновлены. |
| `preview_edit` | Те же предусловия, что у планируемой ручной операции; совпадает `expected_revision` | `PreparationEditPreview` с метриками и счётчиками до/после без изменения state, RNG, revision и истории. |
| `start_simulation` | Валидное подготовленное состояние | Граница и параметры инициализации становятся доступными только для чтения. |

Ключевые поля DTO: `initialization_mode`, `seed_init`, параметры `μ/σ`, счётчики `N0/N_atoms/NV/NI/NAs`, фаза `preparation|simulation`, `PreparationEditPreview`, `DestinationOption.selectable/block_code`, предупреждения вместимости и структурированные ошибки.

## 8. Ошибки

| Код | Условие |
|---|---|
| `INVALID_DEFECT_COUNT` | Отрицательное значение, `NV>N0` или нарушено ограничение симметричного режима. |
| `INITIAL_CONFIGURATION_INFEASIBLE` | Заданные/разыгранные количества нельзя разместить, сохранив вместимость и связность. |
| `BOUNDARY_LOCKED` | Попытка изменить границу после первого акта. |
| `EDIT_NOT_ALLOWED` | Добавление/удаление после старта или изменение в неподходящей фазе. |
| `SIMULATION_NOT_PAUSED` | Ручной перенос после старта во время выполнения. |
| `DISCONNECTED_ATOM` | Операция оставляет межузельный/внешний атом изолированным. |
| `EXTERNAL_REENTRY_FORBIDDEN` | Красный атом пытаются вручную вернуть в область металла. |

## 9. Приёмочные тесты модуля

| ID | Сценарий | Ожидаемый результат |
|---|---|---|
| INIT-01 | Создать `ordered` в 2D и 3D | `NV=NI=NAs=0`, `N_atoms=N0`, `D=0`, `S=0`. |
| INIT-02 | Создать `explicit_defective` с независимыми счётчиками | Формула `N_atoms=N0−NV+NI+NAs` выполнена; нет ложного парного ограничения. |
| INIT-03 | Создать `symmetric_defective` | Приняты только конфигурации с `NI+NAs=NV` и `N_atoms=N0`. |
| INIT-04 | Дважды создать случайную конфигурацию с одинаковым seed | Полностью совпадают счётчики, позиции и журнал подготовки. |
| INIT-05 | Попросить невместимое/несвязное число внешних атомов | Ошибка без частично созданной симуляции. |
| INIT-06 | До старта добавить, удалить и перенести атом | Счётчики и история подготовки обновлены. |
| INIT-07 | После старта попытаться добавить/удалить атом и изменить границу | Операции отклонены. |
| INIT-08 | На паузе после старта перенести существующий атом | Создан `manual_edit`, обновлены метрики; физический акт не засчитан. |
| INIT-09 | Попытаться изолировать или вернуть красный атом внутрь металла | Операция отклонена с правильной причиной. |

## 10. Граница ответственности

- `topology` хранит геометрию и проверяет связность; он не решает, сколько дефектов нужно создать.
- `simulation_management` владеет состояниями «Подготовка»/«Симуляция», RNG, checkpoint и `undo/redo`.
- `events` начинает работать только после `start_simulation`; обычные акты не добавляют и не удаляют атомы.
- `metrics` пересчитывает счётчики, `D` и `S` после каждого успешного изменения.
- `src` даёт элементы ввода и предпросмотра, но проверка допустимости остаётся на сервере.
